DESIGN DELIVERED (per brief, with sources)
==============================================================================
- RepoRef (public struct, Sendable + Hashable): validated owner/repo — ASCII
  alphanumerics + - _ . only, both parts non-empty, private init + failable
  RepoRef.validated(owner:repo:); `slug` = "owner/repo" cache-key form.
- GithubSource (public struct: UpdateSource, Sendable; static kind .github):
  1. init(pinnedOwner:pinnedRepo:directory:session:) — pinned repo is the
     ONLY candidate; invalid pin = explicit empty list (never a harvest
     fallback), honest nil with zero requests. Built for the manual-sources
     lane's coordinator wiring.
  2. init(repoProvider: (@Sendable (InstalledApp) async -> [RepoRef]?)? = nil,
     directory: URL, session: URLSession) — directory REQUIRED (non-optional)
     in both inits, exactly as the brief amended: tests pass unique temp
     dirs; production wires the real directory at integration. nil provider
     → default harvest from app.sparkleFeedURL ONLY: https + host exactly
     "github.com" / "githubusercontent.com" / "raw.githubusercontent.com" →
     first two path segments (trailing ".git" stripped). Provider returning
     [] = active "no candidates" (suppresses harvest); nil = fall back to
     harvest; >2 refs capped to first 2 UNIQUE, order preserved.
  3. GET https://api.github.com/repos/<owner>/<repo>/releases/latest with
     Accept: application/vnd.github.v3+json, User-Agent: AppUpdater/0.1
     (macOS), If-None-Match from the persisted cache. 304 → cached verbatim
     body; 200 → persist(etag+body) THEN parse; 404 → next candidate / nil;
     403 + X-RateLimit-Remaining=="0" → THROW verbatim "GitHub API rate
     limit exhausted (403) — releases/latest for '<owner>/<repo>'"
     (GithubRateLimitError; surfaces via UpdateCheckEngine.failures through
     String(describing:)); everything else honest miss.
  4. Parse: tag_name REQUIRED verbatim (missing/blank → skip; never
     synthesized), published_at ISO8601 (+fractional-seconds variant,
     missing → nil), body → releaseNotes, assets[].name +
     .browser_download_url. Asset pick tie-break: .dmg > .zip; within the
     winning tier the first arm64/aarch64 name beats everything else
     (x64-labeled and unlabeled rank equally, array order decides);
     never .exe/.deb/.rpm/.apk/.AppImage/.pkg; no eligible asset →
     downloadURL nil = info-only claim (install side already refuses
     unverifyable bytes). HTTPS-only floor: asset browser_download_url must
     be https or it is skipped from the pick.
  5. SHA-256 sidecar: asset named EXACTLY "<chosen>.sha256" → one extra
     https GET, FIRST whitespace token must be exactly 64 hex chars →
     sha256Hex (lowercased) + confidence .high; otherwise sha256Hex nil +
     .medium + sourceDetail says "self-attested upstream source".
  6. UpdateInfo: source .github, newestShortVersion = tag verbatim,
     newestBundleVersion nil, minimumSystemVersion nil (release JSON exposes
     no macOS floor), releaseDate, releaseNotes = body,
     sourceDetail = "github: <owner>/<repo>; release asset '<name>'" (+ sidecar
     verify note / self-attested note as applicable).
- ETag cache: <directory>/github_etag_cache.json, Updatest-shape
  {"etags": {"<owner>/<repo>": "<raw etag>"},
   "responses": {"<owner>/<repo>": last release JSON verbatim}}; "verbatim"
  = body stored as a JSON string value (Data→String→Data round-trips
  byte-exactly for UTF-8; a re-serialized object would NOT be byte-verbatim).
  Atomic write (unique staging file + same-volume replaceItemAt/moveItem
  swap), createDirectory first, corrupt file tolerated as "no cache"
  (self-heals on next 200), persistence best-effort (write failure never
  blocks the claim), reload-merge before persist (racing writes bounded:
  worst case loses an entry, never byte integrity).

HONEST ASSUMPTIONS & LIMITATIONS (decisions the brief left open, recorded for
merge review; nothing was silently guessed where the brief was silent)
==============================================================================
1. No artifact-vs-app validation: a github claim is NOT checked against the
   app's name/bundle (CaskSource-style matching does not apply). Evidence
   basis (UPDATEST-FINDINGS §3.6): the default harvest uses the app's OWN
   Sparkle feed as attestor, and manual pins are user attestations
   (Updatest's "username/repo (optional)" model). Documented in the source
   header, not hidden.
2. sourceDetail for the no-asset path is a lane-decision string: "github:
   <owner>/<repo>; no matching macOS release asset — info-only claim" (+ the
   self-attested note). The brief fixed only the asset-present form; the
   no-asset case had to say something and says exactly what is true.
3. Rate-limit throw is IMMEDIATE (not after trying remaining candidates):
   the limit is account/IP-wide, a second attempt would just 403 again, and
   a diagnosable failure must not be demoted to a silent nil.
4. Unverified claims label themselves "sha256 self-attested upstream source
   (not verified)" inside sourceDetail and ride at confidence .medium —
   mirroring Updatest's in-product honesty label ("Best-effort update
   detection. May be rate limited.", "GitHub release data may be inaccurate
   and downloads are not verified by Updatest") without importing their
   wording wholesale.
5. The sidecar fetch is NOT etag-cached (cache keys are owner/repo
   granularity; the sidecar costs at most one extra request per check —
   bounded, documented).
6. Other *.githubusercontent.com subdomains (e.g. objects.githubusercontent)
   are deliberately NOT harvested in v1 — narrower beats wilder, exactly the
   three brief-locked hosts.
7. ETag header absent on a 200 → nothing persisted (an un-etagged body can
   never be conditionally reused, so caching it is unusable ballast).
8. The etag304 + cross-store tests use STRONG etag fixtures ("..."): Swift
   Testing/CFNetwork canon re-quotes weak-validator ("W/...") header values
   through the URLProtocol stub path, so byte-verbatim round-trip of a W/
   form could not be pinned in a hermetic test; the source persists whatever
   header value it actually received, verbatim — that is the honest seam.
9. swiftlint style warnings (file_length, type_body_length,
   cyclomatic_complexity 11 on the status-map switch,
   optional_data_string_conversion for the tolerant UTF-8 decode,
   static_over_final_class mirrors of the Cask/MASSource stub pattern) remain
   — the calibrated gate counts ERROR severity, which is 0.
