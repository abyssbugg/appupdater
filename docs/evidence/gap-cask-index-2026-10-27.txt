HONEST NOTES
------------

1. Compile-forced API-visibility deviation (FLAGGED FOR COORDINATOR). The brief
   sketched `public func bestMatch(for:) -> CaskRecord?` and
   `public func record(withToken:)`. Swift rejects a public member whose
   signature exposes the module-internal `CaskRecord` (it lives in
   CaskResponse.swift, a SHARED file outside this lane's ownership — therefore
   not made public here). These members are compiled INTERNAL:
     internal members: CaskIndexStore.bestMatch(for:),
     CaskIndexStore.record(withToken:), CaskIndexStore.resolvedMatch(for:)
     and the internal enum CaskIndexMatch (token / artifactName + basisFragment).
   Tests reach them via @testable import. ensureLoaded, dropCache, isLoaded,
   cachedRecordCount, lastError ARE public as briefed. If another module ever
   needs direct record access, opening up CaskRecord is a shared-file decision.
   (Compiler probe in this session confirmed the exact error: "method cannot be
   declared public because its result uses an internal type".)

2. Actors cannot declare `convenience` initializers — the production
   convenience `CaskIndexStore.init(directory:)` is a plain delegating
   designated init (role identical to CaskSource's double-init pattern).

3. ensureLoaded runs ONE full cycle per sequential call (disk decode skipped
   when memory already holds records, then ONE conditional GET — 304-expected in
   steady state). Deliberately NOT session-memoized: the literal brief. AppState
   wiring should call ensureLoaded() once per scan pass, then bestMatch per app
   (CaskIndexSource.fetchUpdateInfo deliberately does NOT ensure itself).

4. lastError contract (verbatim, tested): "HTTP <code>" for non-2xx statuses
   (minus the 304-handled case), e.g. "HTTP 500" / "HTTP 503";
   "HTTP 304 without a usable cached cask.json" for the protocol-absurd 304;
   String(describing:) for thrown network/decode errors (asserted via
   NSURLErrorDomain); "non-HTTP response from ..." for a non-HTTP response.
   lastError is cleared at the start of each cycle and by dropCache.

5. Decode-BEFORE-persist ordering (self-heal, slight deviation from the
   brief's "persist bytes+etag+decode" list): a 200 body is decoded FIRST; an
   undecodable body never clobbers a good cache and never records an ETag for
   bytes the store cannot decode (which would otherwise pin dead bytes on a 304
   loop forever). Poisoned-disk test pins the behavior: no If-None-Match after a
   disk decode failure, unconditional GET recovers.

6. Stale-serve decision: when a cycle's NETWORK leg fails but usable records
   were loaded (from disk this cycle or from memory), the records STAY
   available; ensureLoaded returns false and lastError carries the revalidation
   failure. ensureLoaded's Bool = "this cycle revalidated/refreshed cleanly",
   not "records are usable" — pin by isLoaded/cachedRecordCount/lastError.

7. Matching: token path (derived token + artifact validation) then the
   validation-identical whole-index artifact scan (the alias-killer). Ties prefer
   displayName == app.name case-insensitively (tested: exact-name beats EARLIER
   array order); no tiebreak → first in index order, ambiguity recorded via
   os.Logger notice (category cask-index) — log output itself is NOT asserted.

8. Persist-failure honesty: cask.json/etag persistence failures are logged once
   (error level) but never fail the cycle — the in-memory index is what the
   session matches against; lastError tracks only the status/network/decode
   pipeline per the brief. etag deletion mid-session costs one full GET next
   cycle (honest degradation).
