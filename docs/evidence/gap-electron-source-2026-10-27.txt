DESIGN DECISIONS (all per brief)
--------------------------------------------------------------
- SourceKind .unknown — coordinator-owned enum REUSED, no new kind.
- Pipeline A (app-update.yml; presence wins): provider "github"+owner+repo →
  GET https://api.github.com/repos/<owner>/<repo>/releases/latest (Accept:
  application/vnd.github.v3+json) → asset NAMED exactly "latest-mac.yml" →
  download (< 64 KB guard) → parse. Any other provider WITH a plain url →
  GET <url>/latest-mac.yml (HTTPS-only floor). Everything else (s3, custom,
  no provider key, http url) → Pipeline B fallback, else honest nil.
- latest-mac.yml → claim: version REQUIRED (never synthesized);
  downloadURL = first usable files[].url — RELATIVE joins the yml origin's
  directory, absolute wins; sha256Hex = nil ALWAYS (only SHA-512 exists
  upstream; our installer verifies SHA-256 ⇒ info+manual by design — the
  sourceDetail says so verbatim); minimumSystemVersion nil; releaseDate
  ISO8601-first; releaseNotes = releaseName; confidence .medium.
- Pipeline B (asar): header JSON → package.json → "main" (default
  "index.js") → slice → Updatest's regexes
  ( updateURL\s*[=:]\s*['"`]([^'"`]+)['"`] and
    ['"`](https?://update\.electronjs\.org/[^'"`]+)['"`] )
  → owner/repo = first two path segments after the host (any
  {platform}/{version} suffix stripped by construction) → probe
  https://update.electronjs.org/<owner>/<repo>/darwin-arm64/<installed
  shortVersion ?? bundleVersion ?? "0.0.0"> → JSON {name, version, url?}
  with version REQUIRED. Non-electronjs updateURL values and non-https
  probe urls are refused by the LOCKED https floor (honest nil / nil url).
- Failure semantics: every network/parse failure yields nil; the declared
  `throws` is the frozen UpdateSource contract and this source never
  rethrows (malformed URLs included — CaskSource-style honest nil).

  u32LE[0..4)   = 4                  (size-pickle payload constant)
  u32LE[4..8)   = 0x2E034 = 188468   (H — header pickle buffer length)

  Cross-checks that all agree (both derivations of the data base):
    align4(J)        = 188460
    S  = 4 + align4(J)              = 188464 ✓ (matches byte [8..12))
    H  = 4 + S                      = 188468 ✓ (matches byte [4..8))
    data_base = 8 + H = 16 + align4(J) = 188476 ✓
  Payload slice proof: header entry /package.json = {size 1121,
  offset "47385950" (STRING — reader accepts String|Int)} → bytes at
  data_base + 47385950 parse as package.json
  {@ant/desktop, 4.29.0, main: ".vite/build/index.pre.js"}; the main file
  (1,002,540 bytes) then slices cleanly at data_base + its own offset.
  Conclusion: the real-world offsets AGREE with the public asar
  spec assumption; the reader codes exactly the observed layout.

LIMITATIONS (honest, all also documented in source doc comments)
--------------------------------------------------------------
1. PLATFORM TEMPLATE (pipeline B): the electronjs probe is hardwired
   darwin-arm64 (brief-locked emulated probe). Updatest scrapes per-arch
   templates; probing darwin-x64 (or arm64-only apps on Intel) is deferred.
2. YML ARCHIVE VARIANTS (pipeline A): only the base name latest-mac.yml is
   fetched. latest-mac-arm64.yml / latest-mac-universal.yml / RELEASES.json
   (the Updatest-documented family) are deliberately v1-skipped, as are
   channel-specific compositions (Notion's yaml `channel: arm64` is parsed
   but unused). Consequence: channel/arch staging of a release may be
   missed → honest nil or an older-than-newest version claim.
3. FIRST-ENTRY downloadURL pick: electron-builder lists x64+arm64+universal
   artifacts in one files[] list; v1 takes the first usable entry and does
   NOT arch-match against this Mac. Recorded for merge review — refine at
   install-time when arch awareness lands (info+manual tier today).
4. S3 / CUSTOM providers are NOT routed to their endpoint/bucket
   composition (real shapes: Bionic s3, Linear/Termius custom) → Pipeline B
   else honest nil. The s3 URL algebra is deferred (v1 scope per brief).
5. UNPACKED asar members (app.asar.unpacked/) are skipped — the main script
   of Figma/Slack/Factory/1Password is not readable through this v1 reader
   → honest nil for those apps. GitHub-optional integration belongs to the
   `.github` (engine-wired) story, NOT this lane.
6. NO installed-version staleness gating (recorded consequence for merge
   review, like SparkleSource's per-lane note): an equal-or-stale electron
   release stays a claim. Rationale: the claim is "what the vendor
   publishes" for an app that self-updates at launch — Updatest's framing —
   and the engine's unknown-gating already places it LAST. If the
   coordinator wants Sparkle-parity ("not newer ⇒ nil"), it is a two-line
   addition in `claim(from:ymlOrigin:)` / `claimFromAsar` — flagged, not
   preemptively applied (the brief pins the claim semantics verbatim).
7. INTEGRATION (coordinator): wire `ElectronSource()` into the engine's
   source array (AppState/UpdateCheckEngine cli/app init sites — see
   UpdateCheckEngine docs; SourceKind .unknown → engine keeps it last and
   VersionOracle surfaces the claim only when no stronger source exists).
   The kind string surfaces as "unknown" in JSON reports (SourceKind
   rawValue) — coordinator may want a friendlier report label later;
   that is report/UX surface, not model enum, and stays theirs.
8. updateURL pointing at NON-electronjs hosts is recorded-but-unrouted
   (v1 = electronjs-hosted service only, per brief wording).
